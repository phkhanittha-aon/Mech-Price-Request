# MGS Pricing — การแจ้งเตือน Lark (v5.0 · กลุ่มเดียวทุกคน แบบระบบขอราคา Food)

ค่าเริ่มต้นคือ **dry-run**: ระบบสร้างการ์ดครบทุกขั้นตอนแล้วเก็บไว้ในแท็บ `NotifyQueue` (Status = `DRYRUN`) โดยยังไม่ส่งเข้ากลุ่ม
เมื่อตรวจแล้วพร้อม ให้เปลี่ยน Script Property `LARK_MODE` เป็น `live` (ไม่ต้องแก้โค้ด)

## หลักการ (ตามที่ตกลง)
- **มีกลุ่ม Lark กลุ่มเดียว** และทุกคนอยู่ในกลุ่มนั้น: Sales · Sourcing · Sourcing Manager · BD Manager · GM · NON
- **การ์ดแสดงแค่สถานะ** ว่าคำขออยู่ขั้นไหนและรอใคร **ไม่มี ราคา ต้นทุน %GP มูลค่า หรือชื่อผู้ขาย** เพราะทุกคนในกลุ่มเห็นการ์ด
  ส่วนราคาให้ดูบนเว็บ ซึ่งเห็นตามสิทธิ์ของแต่ละคน
- **@แท็กคนที่ต้องทำต่อ** โดยใช้อีเมลในคอลัมน์ `Email` ของแท็บ Users ซึ่งต้องตรงกับอีเมลบัญชี Lark
- **ไม่มีแจ้งเตือนงาน follow-up** ของ Sales (การติดตามลูกค้าหลังได้ราคา) และไม่มีสรุปประจำวัน
- เมื่องานเกินกำหนด **บอทอีกตัวจะเตือนแยก**

## 0. ตั้งค่า (ทำครั้งเดียว · ประมาณ 10 นาที)
1. สร้างกลุ่ม Lark เช่น **"MGS Price Request (Mech/Solar)"** แล้วเชิญทุกคนเข้ากลุ่ม
2. เพิ่ม Bot A: ตั้งค่ากลุ่ม → Bots → Add Bot → **Custom Bot** → ตั้งชื่อ `MGS Price Request`
   - คัดลอก **Webhook URL**
   - Security settings → เปิด **Signature verification** แล้วคัดลอก **Secret**
   - **ห้ามเปิด** Custom keywords และ IP whitelist
3. เพิ่ม Bot B ด้วยวิธีเดียวกัน ตั้งชื่อ `MGS Reminder` (ไม่บังคับ ถ้าไม่ตั้ง การ์ดเตือนจะส่งผ่าน Bot A)
4. Apps Script → ⚙️ Project Settings → **Script properties** → เพิ่มค่าต่อไปนี้ (ห้ามใส่ในโค้ดหรือในชีท)

| Property | ค่า |
|---|---|
| `LARK_BOT_URL` | Webhook URL ของ Bot A |
| `LARK_BOT_SECRET` | Secret ของ Bot A |
| `LARK_REMINDER_URL` | Webhook URL ของ Bot B (ไม่บังคับ) |
| `LARK_REMINDER_SECRET` | Secret ของ Bot B |
| `LARK_MODE` | `dryrun` ช่วงทดสอบ แล้วเปลี่ยนเป็น `live` |
| `LARK_MENTION_REQUESTER` | `on` (ค่าเริ่มต้น) = แท็ก Sales ผู้ขอทุกการ์ด · `off` = แสดงเป็นชื่ออย่างเดียว |
| `APP_URL` | URL `/exec` ของ Web App (ไม่บังคับ ถ้าไม่ใส่ระบบหาเอง) |

5. ตรวจคอลัมน์ `Email` ในแท็บ Users ว่าทุกคนมีอีเมลตรงกับบัญชี Lark
6. รันใน Editor ตามลำดับ:
   - `larkCheckConfig()` → ต้องไม่มี problems และแจ้งชื่อคนที่ยังไม่มีอีเมล
   - `larkTestSend()` → ส่งการ์ดทดสอบ 3 ใบโดยแท็กอีเมลของคุณ ถ้าชื่อในช่อง "ผู้ดำเนินการ" เป็น **สีฟ้า** แปลว่าแท็กได้
   - `larkInstallTriggers()` → ติดตั้ง `larkFlush` ทุก 5 นาที และ `larkSlaScan` ทุกชั่วโมง พร้อมลบ trigger สรุปประจำวันของ v4.9
7. ใช้งานแบบ `dryrun` 1–2 วัน ตรวจการ์ดในแท็บ `NotifyQueue` (คอลัมน์ Payload) แล้วตั้ง `LARK_MODE` = `live`

> ค่าของ v4.9 (`LARK_WEBHOOK_SOURCING / APPROVERS / RELEASE / SALES / URL`, `LARK_APP_ID`, `LARK_CHAT_*`) ไม่ใช้แล้ว และลบได้
> ถ้ายังมี `LARK_WEBHOOK_REQUESTS` (กลุ่มคำขอราคาของ v4.9) แต่ยังไม่ได้ตั้ง `LARK_BOT_URL` ระบบจะใช้ค่านั้นแทน Bot A ไปก่อน

## 1. ตาราง event (`LARK_EVENTS` ใน `Lark.gs` — ที่เดียว)

| Event | หัวการ์ด | เกิดเมื่อ | @แท็ก (ผู้ดำเนินการ) | บอท |
|---|---|---|---|---|
| `SR_SUBMITTED` | 📥 คำขอราคาใหม่ → Sourcing | Sales ส่งคำขอ (SR) | Sourcing ที่ดูแลกลุ่มสินค้านั้น (ถ้าไม่ระบุคน = ทีม Sourcing ทุกคน) | A |
| `SR_FORWARDED` | 🔀 ส่งต่อคำขอราคา | ทีมภายในกด "ส่งต่อ" | ผู้รับคนใหม่ | A |
| `SR_ACCEPTED` | 🔧 Sourcing รับงานแล้ว · กำลังทำราคา | Sourcing กดรับงาน | คนที่รับงาน | A |
| `SR_CANCELLED` | 🚫 ยกเลิกคำขอราคา | คำขอถูกยกเลิก | ผู้รับคำขอ | A |
| `QT_SUBMITTED` | 📊 ทำราคาเสร็จ · รอ Sourcing Manager อนุมัติ (ระดับ 1) | Sourcing ส่งขออนุมัติ | ทุกคนที่มี role Procurement Mgr (= Sourcing Manager) | A |
| `QT_LEVEL1_APPROVED` | 🏁 Sourcing Manager อนุมัติแล้ว · รอ BD Manager (ระดับ 2) | ระดับ 1 อนุมัติ (หรือ GM แทน) | BD Manager | A |
| `QT_APPROVED` | ✅ อนุมัติครบ 2 ระดับ · รอปล่อยราคา | ระดับ 2 อนุมัติ (หรือ GM แทนครบ) | NON (และผู้ปล่อยราคาสำรอง) | A |
| `QT_RETURNED` | ↩️ ตีกลับแก้ราคา | ผู้อนุมัติส่งกลับ | Sourcing ผู้ทำราคา | A |
| `PRICE_RELEASED` | 🎉 ปล่อยราคาแล้ว · Sales ดูราคาบนเว็บ | NON กดปล่อยราคา | Sales ผู้ขอ | A |
| `SLA_REMINDER` | ⏰ งานค้างเกินกำหนด | ตรวจทุกชั่วโมงในเวลาทำงาน จ.–ศ. 08:30–17:30 | คนที่งานค้างอยู่ | B |

**ช่องในการ์ด:** เลขที่ · ลูกค้า (+ ชื่อโครงการ) · ผู้ขอ (@) · สถานะ · ผู้ดำเนินการ (@) · ครบกำหนด
ตามด้วยแถบขั้นตอน `✅ ส่งคำขอ › ✅ Sourcing ทำราคา › 🔶 Sourcing Manager › ⚪ BD Manager › ⚪ ปล่อยราคา`
แล้วเป็นรายการสินค้า (รหัส ชื่อ จำนวน และหน่วย ไม่มีราคา) และข้อความ "💰 มีราคาแล้ว — ดูราคาบนเว็บ" เมื่อทำราคาแล้ว
ท้ายการ์ดมีปุ่ม **เปิดรายการ** (`?doc=<id>`) ซึ่งระบบเลือกหน้าให้เองตามอีเมลของคนที่กด

**กันส่งซ้ำ:** event เดิมของเอกสารเดิมในรอบเดิม ส่งได้ครั้งเดียวภายในระยะ `dedupMin` ถ้าเปิดรอบใหม่ (R2) จะแจ้งได้อีก
**การเตือน:** ส่งได้วันละครั้งต่อหนึ่งงานต่อหนึ่งขั้นตอน และสูงสุด 15 ใบต่อชั่วโมง โดยงานที่เกินกำหนดนานที่สุดขึ้นก่อน
งานติดตามลูกค้าของ Sales (หลังปล่อยราคา) จะไม่ถูกเตือน

## 2. โครงสร้าง
1. **BUILD** — `larkBuild_()` เป็น pure function (ไม่มี I/O) แปลงข้อมูลเป็นการ์ด interactive
2. **QUEUE** — `larkEnqueueMany_()` เขียนลงแท็บ `NotifyQueue` ภายในธุรกรรม และ **ไม่ยิง HTTP** ถ้าล้มเหลวการบันทึกหลักยังสำเร็จ
3. **SEND** — `larkFlush()` (ทุก 5 นาที) ส่งทั้งชุดด้วย `UrlFetchApp.fetchAll` พร้อมลายเซ็น HMAC
   - ถ้าส่งไม่สำเร็จ ลองใหม่หลัง 1 / 5 / 15 / 60 / 180 นาที ครบแล้วบันทึกเป็น `FAILED` และลง Log `lark-failed`
   - ถ้าข้อผิดพลาดเป็นเรื่อง Secret / keywords / IP ระบบเติมคำแนะนำไว้ในคอลัมน์ LastError
4. **REMINDER** — `larkSlaScan()` (ทุกชั่วโมง) ใช้ `followState_()` ตัวเดียวกับหน้าจอ เพราะฉะนั้นวันครบกำหนดตรงกันทุกที่

## 3. ความปลอดภัย
- **ไม่มีตัวเลขเงินในการ์ดเลย** เทสต์ตรวจทุกการ์ดในคิวว่าไม่มี ราคา ต้นทุน กำไร %GP สัญลักษณ์ ฿/US$ หรือ unitPrice
- ข้อความจากผู้ใช้ถูกตัด `< > * _ ~ \` [ ]` และอักขระควบคุมออก จึงสั่ง @ทั้งกลุ่ม หรือแทรก markdown ไม่ได้
- @แท็กสร้างจากอีเมลที่ผ่าน regex เท่านั้น
- Webhook URL และ Secret อยู่ใน Script Properties และ `larkCheckConfig` / `?diag=1` ไม่แสดงค่าจริง

## 4. เครื่องมือ (รันจาก Editor)

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `larkCheckConfig()` | ตรวจการตั้งค่า และบอกผู้ใช้ที่ยังไม่มีอีเมล |
| `larkTestSend()` | ส่งการ์ดทดสอบจริง 3 ใบโดยแท็กคุณ (ไม่สนโหมด) |
| `larkDryRunDemo()` | พิมพ์การ์ดตัวอย่างครบ 10 event โดยไม่ส่งและไม่เขียนชีท (ตัวอย่างเก็บไว้ที่ `docs/lark_payload_samples.json`) |
| `larkInstallTriggers()` | ติดตั้งหรือติดตั้ง trigger ใหม่ (รันซ้ำได้ ไม่ซ้อน) |
| `larkQueueReport(20)` | ดูคิว 20 รายการล่าสุด |
