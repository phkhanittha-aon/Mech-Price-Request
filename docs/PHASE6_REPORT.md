## 3. สิ่งที่ Phase 6 พบ (เรียงตามความรุนแรง)

### 3.1 🔴 CRITICAL — บั๊กเดิมของ production: %GP ลดลงเองทุกครั้งที่โหลดใบใหม่ → **แก้แล้วใน v4.8**
- **อาการ (พิสูจน์บน production จริง):** สร้างใบ GP 18% ยอด 121,951.22 → reload หน้า → GP กลายเป็น 15.254% ยอด **117,999.67 (−3.2%)** · อีกเครื่องที่ดึงจากชีทก็เห็นราคาที่ลดแล้ว
- **สาเหตุ:** `migrateQuotePricing()` แปลง %GP เป็น markup สำหรับใบที่ไม่มีธง `_pm:2` แต่ `blankQuote()` ไม่เคยใส่ธงนี้ → ใบใหม่ทุกใบถูกแปลงซ้ำเมื่อโหลดครั้งถัดไป และราคาที่ลดแล้วถูกบันทึกทับเมื่อมีคนกดบันทึก
- **การแก้:** ใบที่มี `_sv:3` (สร้างจากฟอร์มรุ่น %GP) แต่ยังไม่มี `_pm` → ไม่แปลงตัวเลข แค่ติดธง · ใบใหม่ / SR / QT จาก SR ติด `_pm:2` ตั้งแต่สร้าง · ใบ markup รุ่นเก่าจริง (ไม่มี `_sv`) ยังแปลงเหมือนเดิม
  (เหตุผลที่แยกได้แน่นอน: ใบรุ่นเก่าจะได้ `_sv:3` ในรอบเดียวกับที่ได้ `_pm:2` เสมอ เพราะ `migrateQuote` ทำ pricing ก่อน status)
- **ข้อมูลที่เสียหายไปแล้ว:** แก้อัตโนมัติไม่ได้อย่างปลอดภัย (ไม่รู้แน่ว่าผู้ใช้ตั้งใจเท่าไร) → เพิ่มเครื่องมือ **`auditPricingDrift()`** (อ่านอย่างเดียว) รันจาก Editor หลัง deploy จะแสดงรายการใบ/บรรทัดที่ %GP เป็นเลขแปลก ๆ แต่ย้อนกลับแล้วเป็นเลขกลม เช่น `15.254% → น่าจะตั้งใจ 18%` ให้ Sourcing/ผู้จัดการตรวจและแก้เอง
- **ผลยืนยัน:** ใบที่ production สร้าง (THB / USD / CNY) เปิดใน v4.8 แล้วยอดขาย/ต้นทุน/กำไรตรงกันทุกสตางค์

### 3.2 🟠 MEDIUM — regression จาก Phase 4: Price Term / Incoterm / หน่วยนับที่ผู้ใช้เพิ่มเองในเครื่องหายจาก dropdown → **แก้แล้ว**
- production เก็บรายการที่เพิ่มเองไว้ใน `SETTINGS` ของเครื่องนั้น (Sourcing บันทึก Settings ขึ้นชีทไม่ได้) · v4.6 เปลี่ยนไปอ่านจาก MasterData → ค่าเหล่านั้นไม่อยู่ในรายการ
- แก้: หลังโหลด MasterData ส่งค่าที่เพิ่มเองในเครื่อง (ไม่ใช่ค่าตั้งต้น) เข้า MasterData ครั้งเดียว — ค่าที่ Admin ซ่อนไว้ server ปฏิเสธ จึงไม่แสดงกลับ

### 3.3 🟢 LOW — การแปลงใบ markup รุ่นเก่าปัดเศษ %GP 3 ตำแหน่ง (เดิมมีอยู่แล้ว) → ยอมรับไว้
- ใบ markup 18% ต้นทุน 100,000 → ยอดเดิม 118,000 · หลังแปลง 117,999.67 (ต่าง 0.33 บาท) · เกิดเฉพาะใบเก่ามากที่ยังไม่เคยถูกแปลง · ไม่แก้ เพื่อไม่ให้ยอดของใบที่แปลงไปแล้วในเครื่องอื่นต่างกัน

### 3.4 🟢 LOW — ตัวเดินหน้าจอ `audit_roles` ไม่มี assertion → ปรับตัวรันให้ถือว่าตกเมื่อพบ JavaScript error

**การแก้ assertion ในรอบนี้:** ไม่มีการแก้/ลบ assertion ของเทสต์เดิม · ส่วนที่ปรับใน `compat_production.js` เป็นการแก้วิธีจำลองของเทสต์ใหม่เอง (อ่าน key คิวผิดชื่อ, ใช้ `doSaveQuote` ของ production หลังกล่องตรวจข้อมูล, จำลองการรัน `setup()` ครั้งแรกบนชีทเดิม) — ไม่ใช่การลดเงื่อนไข

## 6. Watch-outs
- ใบที่ production ลด %GP แล้วถูกบันทึกทับ **ยังเป็นราคาที่ลดแล้ว** จนกว่าจะมีคนแก้เอง — `auditPricingDrift` ช่วยหาแต่เป็นการเดา (อาจพลาดถ้าผู้ใช้ตั้ง %GP เป็นเลขไม่กลมเอง หรือฟ้องเกินถ้าตั้งใจใช้เลขอย่าง 15.254)
- **ระหว่างยังไม่ deploy v4.8 บั๊กนี้ยังเกิดต่อทุกวันบน production** — แนะนำให้ deploy โดยเร็ว
- ผู้ใช้ที่ยังเปิดหน้าเก่าค้างไว้ต้อง reload หลัง deploy (ไม่งั้นเครื่องนั้นยังแปลงต่อ)
- เทสต์ใช้ backend จำลอง (gasmock) ไม่ใช่ Google Sheets จริง — UAT บนระบบจริงยังจำเป็น โดยเฉพาะ Google login และสิทธิ์ deploy
