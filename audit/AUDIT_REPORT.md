## สรุปสำหรับผู้บริหาร (อ่าน 1 นาที)

**สิ่งที่ดีแล้ว**
- **Sales ไม่เห็นต้นทุน:** ตรวจ payload จริงทุก endpoint ของ Sales, Sales Manager และ NON แล้ว ไม่พบคีย์ต้นทุนเลยแม้แต่ตัวเดียว localStorage ของแอป Sales ก็ไม่มีต้นทุน
- **ลูปงานเดินครบ:** SR → รับงาน → QT → อนุมัติ 2 ฝ่าย → NON ปล่อยราคา → Sales เห็นราคา → Won เจ้าของงานถูกคนทุกขั้น
- **token:** หมดอายุ ปิดบัญชี หรือแอบเข้าหน้าที่ไม่มีสิทธิ์ ทั้งหมดถูกปฏิเสธที่ server

**สิ่งที่ต้องแก้ก่อน (Critical 3 ข้อ)**

1. **ข้ามการอนุมัติ / ปล่อยราคาได้ (C-1)**
   - action `save` เชื่อ Status / ReleasedTo / approvals ที่ client ส่งมา
   - ผลคือ Sourcing คนเดียวทำให้ใบเป็น "Approved" หรือ "ปล่อยราคาให้ Sales แล้ว" ได้ โดยไม่มีผู้บริหารคนไหนกดอนุมัติ
   - ปุ่ม "ปล่อยราคา" และ "อนุมัติแบบ offline" ในหน้า Index ก็ใช้ช่องทางนี้เอง
   - เข้าเกณฑ์ที่ Aon ตั้งไว้ว่า "สิทธิ์ตัดสินฝั่ง client = Critical"
2. **XSS ที่ฝังถาวรในข้อมูล (C-2)**
   - Sales ใส่โค้ดลงช่อง "ต้องการภายใน" / "วันที่ขอราคา" หรือในรหัสเอกสาร SR ได้
   - โค้ดนั้นจะรันบนเครื่อง Sourcing และผู้บริหารที่เปิดคิว SR → ขโมย token หรือสั่งงานแทนได้ (ยืนยันแล้วบน Chromium)
3. **ประวัติแก้ไข (audit trail) แก้ทับและหายได้ (C-3)**
   - ประวัติในใบมาจาก client ทั้งก้อน จึงแก้หรือลบได้
   - แท็บ Log เก็บแค่ 5,000 แถวล่าสุด (ประมาณ 2–3 เดือน) และไม่มีค่า "ก่อน → หลัง"
   - ฝ่ายในเขียนทับ SR ที่มี QT แล้วได้ และลบใบที่อนุมัติแล้วได้ทันทีโดยไม่ต้องให้ใครอนุมัติ

**เรื่องที่จะเริ่มเจ็บเมื่อข้อมูลโต**
- เมื่อมีเอกสารรวมเกิน **1,500 ใบ** ใบเก่าจะหายจากหน้าจอแบบเงียบ ๆ
- localStorage ของ Index จะเต็มที่ประมาณ **500 QT**
- ใบที่มีมากกว่าราว **200 รายการ** ถูกตัดทั้งใบเหลือแค่ `{id,_oversize}` แต่ server ยังตอบว่าบันทึกสำเร็จ

## 2) Findings แยกตามความรุนแรง

ทุกข้อด้านล่างพิสูจน์แล้ว (✔) ด้วยสคริปต์หรือหน้าจอจริง เว้นข้อที่เขียนว่า "อ่านโค้ด"

### 🔴 Critical

#### C-1 · ข้ามการอนุมัติ 2 ฝ่าย / ข้ามผู้ปล่อยราคาได้ (สิทธิ์ตัดสินฝั่ง client)

**อะไร:** action `save` ต้องการแค่สิทธิ์ `writeQuote` จากนั้นเขียนค่าต่อไปนี้ตามที่ client ส่งมาทั้งหมด:
- `Status`, `ReleasedTo`, `NeedsApproval`
- `Detail.approvals` / `approvalRoles`
- `Total` / `Cost` / `GP`
- `SalesDetail` (ราคาที่ Sales เห็น)

**ที่ไหน:**
- Code.gs:647–716 `saveQuote_` โดยเฉพาะบรรทัด 699 (Status) และ 702 (ReleasedTo)
- Index.html:4106 `doRelease`: ไม่เรียก action `release` ของ server เลย แต่ตั้งสถานะในเครื่องแล้วส่ง `save`
- Index.html:4035 `approveLocal`

**Role ที่ทำได้:** Sourcing, Procurement Mgr, BD Mgr, GM, Admin (ทุก role ที่มี writeQuote)

**ทำซ้ำได้ (✔ audit_server.js §4):**
1. Sourcing ส่ง `save` พร้อม `status:'Approved'` ผลคือ `ok:true, status:Approved, approvals:[]`
2. Sourcing ส่ง `save` พร้อม `status:'Pending', releasedTo:'boss'` ผลคือ BOSS เห็นราคาทันที โดยไม่มีใครอนุมัติหรือปล่อย
3. บันทึกใบที่อนุมัติไปแล้ว 1 ฝ่ายซ้ำ ประวัติการอนุมัติหายเหลือ 0
4. ส่ง Cost=999999 / GP=-99 ตัวเลขนี้ลงชีทจริง
5. ส่ง SalesDetail ราคา 1 บาท Sales เห็น 1 บาท ทั้งที่ Detail ระบุราคาอื่น

**ทำไมสำคัญ:**
- การควบคุม 2 คน (Procurement + BD) และ NON เป็นด่านคุมราคา ด่านนี้ถูกข้ามได้โดยคนเดียว
- เป็นการตัดสินสิทธิ์ฝั่ง client ซึ่งผิดข้อกำหนดโดยตรง

**แก้:**
- ใน `saveQuote_` ให้ Status เปลี่ยนได้เฉพาะตามตารางสถานะที่ server ถือไว้ สำหรับ action `save` อนุญาตเฉพาะ Draft → In Progress → Submitted (และ Won/Closed/Lost จาก Pending)
- ห้ามเปลี่ยนเป็น Partial Approved / Approved / Pending ผ่าน `save`
- `ReleasedTo` / `approvals` / `approvalRoles` อ่านจากชีทเสมอ ไม่รับจาก client
- เปลี่ยน `doRelease` ให้เรียก `release`
- ระยะถัดไป ให้ server คำนวณ Total/GP และ SalesDetail เอง (ดูหัวข้อ 6)

#### C-2 · Stored XSS: Sales ฝังโค้ดที่ไปรันบนเครื่อง Sourcing และผู้บริหาร

**อะไร:** ช่องต่อไปนี้ถูกแสดงเป็น HTML ดิบโดยไม่ escape:
- `header.needBy` (ต้องการภายใน)
- `header.reqDate`, `header.offerDate`
- `id` ของเอกสาร ซึ่งฝังอยู่ใน `onclick="openQuote('${q.id}')"` มีทั้งหมดประมาณ 45 จุด

นอกจากนี้ `esc()` ของ Index ไม่ escape เครื่องหมาย `'` อยู่แล้ว และ `esc()` ทั้งสองไฟล์ไม่ปลอดภัยเมื่อใช้ภายในสตริง JS ของ attribute

**ที่ไหน:**
- Index.html:6528 (needBy ในคิว SR)
- Index.html:6530 และ 6545 (id ใน onclick)
- Index.html:2771 (reqDate ใน editor)
- Index.html:3932 (offerDate ในหน้า preview)
- Index.html:801 (`esc`)
- Sales.html:792–799, 871, 899, 920, 1067 (id ใน onclick)
- ฝั่ง server: `saveSR_` รับ `p.id` และ field ใน header ได้ทุกค่า

**Role ที่ทำได้:** Sales ทุกคน (เป็นผู้โจมตี) → เหยื่อคือ Sourcing / ผู้บริหาร / GM / Admin

**ทำซ้ำได้ (✔ audit_browser.js §B):** BOSS ส่ง SR ที่มี `needBy:'<img src=x onerror=…>'` และ SR ที่มี id `x');window.__xss4=1;('` ผลที่วัดได้:

| ตำแหน่ง | ผล |
|---|---|
| คิว SR | โค้ดรัน 3 ครั้ง |
| คลิกแถว SR | โค้ดรัน |
| เปิด preview | โค้ดรัน |
| สร้าง QT จาก SR | โค้ดใน reqDate รัน |
| ช่องที่ escape แล้ว (title / customer / desc / remarks) | ไม่รัน ✔ |

**ทำไมสำคัญ:**
- โค้ดอ่าน `localStorage.mgs_token` ได้ token นี้ใช้ได้จากทุกที่นาน 12 ชั่วโมง
- ถ้าเหยื่อเป็น GM/Admin โค้ดสั่ง `saveUsers` เลื่อนสิทธิ์ตัวเองได้

**แก้:**
- escape ทุกจุดที่แสดงผล (needBy / reqDate / offerDate / created / updated)
- เปลี่ยน `onclick="f('${id}')"` เป็น `data-id` + event delegation หรือ `esc(JSON.stringify(id))`
- เพิ่ม `'` ใน `esc()` ของ Index
- ที่ server: `saveSR_` ต้องตรวจ `id` ให้ตรง pattern `^[A-Za-z0-9_-]{1,40}$` และตรวจวันที่ให้ตรง `YYYY-MM-DD`

#### C-3 · Audit trail ไม่ทนทาน: แก้ทับได้ หายได้ ไม่มีค่า ก่อน → หลัง

**อะไร:**
1. `Detail.auditLogs` ของ QT มาจาก client ทั้งก้อน client จึงส่งประวัติปลอมหรือลบประวัติได้ (✔ §4: ส่ง `[{timestamp:'2020-01-01',user:'ปลอม'}]` แล้วชีทเก็บตามนั้น)
2. แท็บ Log ตัดเหลือแค่ 5,000 แถวล่าสุด (Code.gs:80 `LOG_KEEP_ROWS`, ตัดที่ :1842)
   - ทุก login และทุกการบันทึกเขียน 1 แถว คาดว่ามีราว 80–150 แถวต่อวันสำหรับผู้ใช้ 12 คน
   - **ประวัติจึงอยู่ได้แค่ราว 1.5–3 เดือน**
3. แถว Log ของการบันทึกมีแค่ `save QT-xxx | id | ชื่อ` (✔ §3) ไม่มีสถานะ/ราคา ก่อน → หลัง ใช้ "อีเมล" ไม่ได้ (เก็บเป็นชื่อ) และการเปลี่ยนเป็น Won ก็บันทึกแค่ว่า "save"
4. `statusLog` ของ QT เป็นรายการว่างหลังเดินครบลูป (✔ §3) เพราะ server ไม่ได้ต่อท้ายให้
5. ฝ่ายในเขียนทับ SR ที่มี QT แล้วได้ (✔ §4: Sourcing คนที่ 2 ส่ง `save` บน SR ผลคือ ok) และเปลี่ยนชนิดเอกสาร SR → QT ด้วย id เดิมได้ (✔)
   - ผิดหลักที่ว่า "SR คือหลักฐานคำขอลูกค้า ห้ามเขียนทับ"

   - ฟังก์ชัน `migrate_vN()` รันครั้งเดียวผ่าน Admin

5. **ตรวจ header ตอนเริ่ม** (H-8) + `?diag` แสดงผล

## 10) คำถามที่ต้องให้ Aon ตัดสินใจ

- **D-1 · Retention:** รับตามข้อเสนอในหัวข้อ 5.3 หรือไม่
  - ใบที่ปิดแล้วอยู่ในชีทหลัก 24 เดือน แล้วย้ายไปไฟล์ Archive รายปี
  - ใบที่ลบย้ายไป Archive หลัง 90 วัน (ไม่ลบถาวร)
  - AuditTrail ไม่ลบ
  - backup ทุกสัปดาห์ เก็บ 8 ชุด + ชุดสิ้นเดือน 12 เดือน
  - ถ้าอยากใช้ตัวเลขอื่น (เช่น 12 หรือ 36 เดือน) แจ้งได้เลย
- **D-2 · ผู้อนุมัติ / ผู้ปล่อยราคาสำรอง:**
  - ตอนนี้ GM อนุมัติแทนได้ทั้ง 2 ฝ่าย (override) แต่ **Admin อนุมัติไม่ได้** ต้องการให้ Admin เป็นผู้อนุมัติสำรองหรือไม่
  - ผู้ปล่อยราคาสำรอง (`releaseDelegateId`) ควรเป็นใคร
  - ปัจจุบัน Procurement Mgr / BD Mgr แก้ค่านี้ใน Settings ได้เอง ต้องการจำกัดให้เฉพาะ GM / Admin หรือไม่
- **D-3 · การลบ:** ใบตั้งแต่ Approved ขึ้นไป "ห้ามลบ ให้ปิดเป็น Lost / Closed แทน" หรือ "ลบได้เมื่อ GM อนุมัติ"
- **D-4 · Sales ปิดงานเอง (M-6):** ให้ Sales (เจ้าของงาน) กด Won / Lost เองได้หรือไม่ หรือยังให้ Sourcing เป็นผู้ปิด
- **D-5 · ลำดับการแก้:** เริ่มชุด 1 (ปิดรูด่วน) ก่อนตามที่เสนอ หรือต้องการสลับลำดับ
